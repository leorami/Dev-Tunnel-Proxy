# Calliope owner review: bind proposal to authenticated intent (isolated CTO research)

Status: **SOURCE-ONLY / INDEPENDENT CTO LANE. NOT WIRED, DEPLOYED, DISPATCHED, OR AUTHORIZATION.**

## Actual V92 source vulnerability

In returned V92 `utils/proxyConfigAPI.js`, authenticated `POST apps/propose-nextjs-redirect-heal` returns exact before/after SHA-256 hashes. The next `POST apps/apply-reviewed-nextjs-redirect` accepts those hashes from the request body and passes `authenticated:true` unconditionally to `runOwnerNextjsRedirectHealSkill` after the route's normal session/Origin check. In `utils/calliope-owner-nextjs-heal-skill.cjs`, the implementation constructs `ownerApproval:{granted:true}` itself when the client hashes match the newly recomputed known fix. The interactive `window.confirm(...)` exists solely in `status/common.js`. The server has **no consumed, session-bound prior review receipt**. An authenticated caller can skip the UI confirmation and call apply directly with known matching hashes. An unknown external attacker is still subject to existing session+Origin controls; do not describe this as unauthenticated remote execution.

This is a **semantic authorization gap**: being signed in and knowing hashes does not prove this operation was separately reviewed. The CAS transaction and HMAC settlement prevent stale changes and unauthorized host commands, but neither proves a particular review interaction occurred. Repairing this issue must not silently strip Calliope's working owner-reviewed healing capability.

## Independent code already written

`utils/rc2-owner-heal-proposal-ticket.cjs` is an *isolated*, process-local pending-review ticket store. Issue only from authenticated, Origin-validated `propose` using `sessionBinding:extractSessionToken(req)` obtained **server-side**; never from the JSON body. It stores only SHA-256 of a 256-bit random token, the 32-byte session identifier, and a SHA-256 digest of exact app+route+before+after hashes. It enforces fixed 120-second TTL, maximum 128 pending tickets, strict schema, no duplicate token overwrite, expiry, session/patch binding and **synchronous consume before asynchronous mutation**. Restart invalidates outstanding tokens. Logout revocation may also be wired. No original source/config or credentials are logged or persisted. The response deliberately declares ownerApprovalGranted:false and executionAuthorized:false even after ticket consumption. The module does not run browser, Docker, shell, OpenAI, host worker or nginx writes.

`tests/security/rc2-owner-heal-proposal-ticket.test.cjs` contains 12 RED-first local Node v22.16.0 regressions, including cross-session, route/app/hash substitution, replay, expiry, rollback clock, RNG failures, cap exhaustion, invalid/poisoned objects, forged approval fields and restart. RED missing-module was demonstrated before GREEN.
