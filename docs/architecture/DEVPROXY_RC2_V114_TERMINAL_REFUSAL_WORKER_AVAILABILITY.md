## Source-proven P1 availability defect
`utils/rc2-cross-process-settlement.cjs` validates `before.candidateSha256` against the signed expected digest **before** `settlement.begin()` or `executeFixedHostAction()`. On mismatch it returns a signed HMAC response `CONFIG_SET_DIGEST_MISMATCH`, persists it under the private response spool, and has never acquired the replay lease or touched nginx. `utils/rc1-content-bound-activation-request.cjs` explicitly recognizes `CONFIG_SET_DIGEST_MISMATCH` as a valid signed reply status.

However `utils/rc2-pending-host-worker.cjs` accepted only `RELOAD_AND_VERIFICATION_REPORTED` and `NGINX_VALIDATION_FAILED` as terminal worker statuses. It threw `HOST_WORKER_INDETERMINATE` even when a **durable, signed no-action rejection** had been returned. That exception propagates through `utils/rc2-exclusive-host-worker-service.cjs` to `HOST_WORKER_SCAN_INDETERMINATE`, intentionally leaving the exclusive singleton lock behind and killing the `--serve` loop. A stale but properly HMAC-signed request can therefore unnecessarily disable the worker. This is independently reproduced on the exact GitHub original `rc2-pending-host-worker.cjs` blob `cb901f7591d31149b2853d3db1b871ed1da90df0`. It is a verified **code path**, not evidence that it caused the current worker death (V113 found the current spool empty).
