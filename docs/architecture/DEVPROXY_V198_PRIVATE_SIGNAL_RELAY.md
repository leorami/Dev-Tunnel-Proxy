### CTO's first real product ingress contract

`utils/calliope-private-signal-admission.cjs` exports `createPrivateSignalCiphertextAdmission`. This Node18-compatible, no-I/O helper will sit **behind** the existing Dev Proxy HTTP management authentication and a **new actual trusted service-to-service sender-enrollment verifier**. It never parses plaintext, signs or decrypts Signal ciphertext, claims successful libsignal handshakes, issues owner grants or performs file operations.

Input envelope has exactly 7 allowlisted values: `version:1`, fixed recipient name, 64-hex message ID, real libsignal message type 2/3, canonical bounded `ciphertextBase64url` (32 to 32768 bytes by default), `createdAtMs`, `expiresAtMs` (max 60 seconds). **Sender and project must NOT appear in client-supplied envelope.** The constructor receives a trusted host-owned, synchronously resolving principal authenticator and enrolled-recipient predicate; untrusted/async/unavailable answers deny. Authenticator's returned exact identity includes sender/project/recipient plus pinned Signal key SHA-256 fingerprints and must match recipient and confirmed enrollment. The object is a *candidate only*, no persistence or delivery; success and denial both always set **all** owner approval, export, execution, healing, live-attestation, and production-change authority flags FALSE.

**Crucial distinction:** Callback injection alone is not a trusted identity provider. A caller able to supply `()=>principal()` and `()=>true` can manufacture a candidate; it MUST NEVER be exposed as an externally callable admission service before the real server hard-wires enrolled-device identity verified by a trusted principal source. Treat successful CI only as structural/negative-contract validation.

### Next Engineer actual application feature (remaining implementation)

Build a single **private ciphertext-only mailbox/data-plane path** in the existing Dev Proxy Config API on an isolated source branch without installing or activating it. Do NOT launch a new listener, local sidecar, public route, Docker service, or model. The configuration must be default **DISABLED/503**, until separately authorized service-to-service authentication, verified principal enrollment, owner session/consent grant and a privately provisioned storage root exist. The only right offered by the mailbox is **deliver encrypted bytes to the exact bound recipient**, not inspect or execute their content.

Safety prerequisites for any route:
1. **Existing ingress auth first.** Reuse the real management session/Origin guard (`classifyManagementRequest`, `requireAuth`, `originDenied`). Beware the existing global `OPTIONS` wildcard CORS handler, which executes before `requireAuth`; no private access based on preflight/Origin/loopback IP, forwarded headers, shared Docker adjacency or browser cookie alone. The admin browser cookie is NOT a service-to-service Signal device identity. Unknown/disabled routes fail closed. No direct port or nginx/ngrok bypass.
2. **Device identity binding.** Trusted host enrollment service validates actual remote principal plus sender and recipient Signal identity fingerprints. User-supplied `sender`, `ownerApproved`, `grantId`, `path`, `url`, `purpose`, `plaintext`, secret keys or message body must never create authority. Pairing is explicit and owner-visible in the actual Trajectory Room and is distinct from V197's test-only issuer key.
3. **Bounded persistence.** Messages require an owner-private 0700 mailbox root outside any nginx-served `.artifacts` or shared mounted project path; 0600 cipher-only entries; recipient-scoped exact IDs, ttl and capacity; replay/idempotency, integrity and fsync-safe delivery/ack after recipient durable processing; no arbitrary filenames, symlink traversal, local file export or unbounded poll. If unavailable, return 503. Source-only tests in ephemeral CI temp, never run on live Mac. A returned queue entry is **opaque ciphertext**, never a decrypted model instruction.
4. **No confusing permissions.** The actual Calliope recipient still must verify a separately authenticated V197 grant + V191 request + V196 replay *after* libsignal decryption, before generating even a metadata response. An authenticated route is not real approval to export screenshots, execute, self-heal, or run a host command.
5. **No false owner UAT.** Product integration needs original screenshot pixels if new UI is built. This Dev Proxy security boundary produces none; do not claim owner app installed SHA or visible build. Real Trajectory pairing UI is separate future cross-repo work, with Origin screenshots retrieved and embedded inline for CTO.
