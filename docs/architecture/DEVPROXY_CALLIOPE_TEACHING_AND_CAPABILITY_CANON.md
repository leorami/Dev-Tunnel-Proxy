## Capability lifecycle and governance
Observe (bounded authenticated local evidence) -> Diagnose (pattern and uncertainty) -> Propose (deterministic exact-diff and new ability request if needed) -> Approve (owner-scoped action/version/target) -> Execute (reviewed transaction/HMAC Mac host worker, only permitted fixed action) -> Verify (nginx syntax, route/browser behavior, preserved 17 routes, recovery) -> Record (success or failure with provenance) -> Refine (draft skill or capability request). No approval is inherited from Cursor's original diagnosis or Calliope's identity.

Read-only observations may be automated within their fixed scope. Writes are performed only through reviewed route transaction with preimage, exact SHA guard, lock, safe rollback and signed host settlement. No API Docker socket, arbitrary commands, privilege expansion, public ngrok changes, blanket HTTPS header changes, credential leaks, silent remote-model access, or automatic elevation from proposal to permission. Local AI is preferred; external processing needs separate explicit owner approval.
