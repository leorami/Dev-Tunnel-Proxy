# RC2 v82 — audited, supervised Mac-host worker and nginx image provenance

**Class:** executable CTO-owned source, Mac integration pending. **No production deployment is claimed.**

## What was actually missing in the returned v81 source

The first operator-run `utils/rc2-mac-host-worker.cjs` accepts a 0600 JSON pin but follows `lstatSync(pinPath)` with a separate `readFileSync(pinPath)`; that opens a path again, so a directory attacker can swap it between checks. It does not establish the pin owner's uid, stable inode, canonical private parent, nor sealed secret source during the read. A run mode `scan-once` scans all historical signed request IDs, not only new ones, so an always-on worker could repeatedly try completed IDs. The returned live Mac has no installed worker, and its image supplied `/etc/nginx/mime.types` and Brotli module fingerprints are not fully bound to a reviewed candidate.

**v82 fixes source rather than assigning these gaps to Engineer-I to reimplement.**

1. `utils/rc2-private-host-worker-pin.cjs` — replaces loose pin loading with actual 0600 `lstat` / `O_NOFOLLOW` file descriptor verification, owner UID, stable dev/inode/mtime/ctime/size, one link, private 0700 parent, and hard-coded exact permitted fields plus fixed nginx mount allowlist. HMAC secret must be separate, private and immutable. The project source root may be 0755 provided it is not group/other writable. No privileged action runs during pin read. Test coverage: 27 RED-first cases.
2. `utils/rc2-pending-host-worker.cjs` — only pending, valid, bounded IDs can reach the existing v13 HMAC `processOne`. Completed IDs with existing private responses are skipped; an existing replay reservation lacking a durable response is an **unresolved crash** and stops scanning. A worker-produced response MUST be durable before advancing to the next request. No automatic replay deletion, retries or stale cleanup. Test coverage: 12 cases.
3. `utils/rc2-exclusive-host-worker-service.cjs` — a single global 0600 O_EXCL + fsync lock serializes requests **across IDs and Mac processes**. Every clean exit verifies lock inode and fsyncs removal; a crash/indeterminate host response retains a quarantining marker until separately authorized manual review. Tests include SIGKILL of a separate Node child and deferred in-flight abort. Coverage: 12 cases.
4. `scripts/rc2-supervised-mac-host-worker.cjs` — actual operator-invoked `--serve` or `--scan-once` entry point that composes the independently tested pin reader, the existing `createMacHostSettlementWorkerFromPin` from PR #79, pending-only queue, and process-exclusive supervisor. Uses host process only. No new Docker container, network listener or auto-install. Requires explicitly supplied absolute private pin path. Returns status only and never logs secret, private path, or route content. Test coverage: 8 cases.
5. `utils/rc2-nginx-image-provenance.cjs` — fixed read-only Mac-host `docker inspect`, `docker exec <pinned-id> nginx -T`, and `docker exec <pinned-id> sha256sum /etc/nginx/mime.types <2 approved Brotli .so>` queries; compares container ID/image/running before and after; validates full `nginx -T` SHA against an independently reviewed pin, exact included config file set and dynamic Brotli directives; checks three image file digests. No shell invocation or mutable Docker commands; no raw nginx dump output. Its output is ALWAYS evidence-only, NEVER owner GO. Test coverage: 17 cases.
