## New CTO security findings — fixed in this source, not deployed

1. V199 Signal endpoint used `openSync(storePath,'w')` to truncate and overwrite the only encrypted ratchet/session/prekey snapshot, risking permanent state loss on crash. CTO isolated real RED-first [Actions #45494109449](https://github.com/leorami/Dev-Tunnel-Proxy/actions/runs/45494109449) (missing atomic-store module), added a private **0600, nofollow, single-writer-lock, fsynced temporary-and-atomic-rename** store; deterministic pre-rename fault injection preserves old bytes. Source now uses this helper for all `createSignalEndpoint` checkpoint loads/writes. Stale writer lock is a *fail-closed recovery task*, never permission to silently rewind/reset ratchets.
2. V199 enrollment registry accepted a mismatched `deviceId` and Ed25519 SPKI fingerprint, silently replaced an already active enrolled role, and quietly filtered malformed enrollment records. Actual RED [Actions #45494619295](https://github.com/leorami/Dev-Tunnel-Proxy/actions/runs/45494619295) **3 failures** demonstrated the defects on Node18/22; CTO added canonical Ed25519 SPKI binding, owner-revocation-required role changes, strict full-file validation and atomic registry writes. Original `nonces.json` read-modify-write risk replaced by **one nonce per O_EXCL-created/fsynced record** in a *preexisting* 0700 `enrollment/proof-nonces` directory. No user secret material may be stored in this public-identity registry. Existing pilot is not enrolled; no installed migration needed.
3. V199 recipient enrollment allowed asymmetric/one-sided Signal identity-pin records. Actual RED [Actions #45494875465](https://github.com/leorami/Dev-Tunnel-Proxy/actions/runs/45494875465) **one test failed**, then required that Trajectory and Calliope each pin exactly the other's libsignal identity fingerprint.
