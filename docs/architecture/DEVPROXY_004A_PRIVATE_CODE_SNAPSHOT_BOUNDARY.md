## Why this matters

The original `utils/calliopeHealing.js` explicitly copies `.env*` into `.artifacts/calliope/resources/` for host source review; its container-project path uses string-interpolated `docker exec <container> sh -lc "cd <path> ..."` and extracts a recursive tar without an app-scoped owner grant. `outName` can be used to construct a destination under that public/previously accessible artifact tree. The control-plane Docker container also has root and a host Docker socket. Source reading alone cannot establish that a private file **was actually copied or publicly accessed**, but these paths must not remain implicit AI authority. The separate, unmerged RC1 perimeter restricts new HTTP ingress but does not retroactively clear historical private files; never read or print them to prove exposure.

## Concrete CTO source decisions (single bounded slice)

1. **Default deny:** no host code snapshot without `CALLIOPE_CODE_SNAPSHOT_ENABLED=1` and an explicit absolute, canonical `CALLIOPE_CODE_SNAPSHOT_APPROVED_ROOTS` list (platform path delimiter separated). The whole filesystem root cannot be approved; source path must be a directory without symlink traversal; full output name is strictly bounded to a portable single path component. This opt-in is **operator configuration**, not a substitute for a per-user authenticated consent grant (future 003/004).
2. **Never place new snapshots in HTTP artifacts:** `PRIVATE_SNAPSHOTS_DIR=.private/calliope/snapshots`, private 0700 leaf and copies 0600. Refuse symlinked storage parents, insecure dir modes, collisions and dangerous Docker mount path delimiters. Private snapshots are excluded by the existing `.gitignore` `.private/` rule. **Do not copy, inspect, delete or migrate existing `.artifacts/calliope/resources/` without owner review.**
3. **No concatenated command strings:** `execFileSync('docker',argv)` with exact isolated `--network none`, `--read-only`, `--cap-drop ALL` and `no-new-privileges`. Bind only the authorized source read-only, a new private output directory, and the fixed copier script. Local Docker image availability must be tested separately; no Docker daemon or live service call was performed by CTO.
4. **Explicit filtered code copy:** `utils/snapshot-copy.js` excludes dotfiles/directories, `.env*`, credential-/token-/secret-/private-named files, symlinks, key files and heavy directories. It bounds per-file bytes (256 KiB), total bytes (5 MiB), file count (400) and recursion (25) and writes 0600 output files. **This is not a content-level secret scanner.** Even a benign-looking source file can contain credentials; owner opt-in and future classified data egress are still necessary.
5. **Container source snapshot disabled intentionally:** the unsafe `docker exec ... sh -lc ... | tar ...` implementation is replaced by a fail-closed `CONTAINER_SNAPSHOT_DISABLED` response. A future full container extractor must implement exact app-owned per-container grants, safe argv and traversal/symlink-safe unpacking before restoring the feature. This temporarily removes implicit container code review capability; preserve that tradeoff for owner UAT rather than silently reintroduce arbitrary shell access.
6. **RED-first focused regression:** `tests/security/calliope-snapshot-boundary.test.mjs` was committed before the implementation. Uses **only test-owned temporary fixtures**, including fake `.env`, service-account metadata and symlinks; asserts default-deny, allowed-root exactness, path/injection/name protection, private output source wiring, safe copy behavior and disabled container tar. No real app data/keys scanned or copied. This suite is intentionally not yet added to the canonical script because RC1 Engineer-I currently owns its `smart-build.sh` test-hook merge.
