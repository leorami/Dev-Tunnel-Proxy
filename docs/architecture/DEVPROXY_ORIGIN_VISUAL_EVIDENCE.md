# Dev Proxy — project-native Origin screenshot capture and delivery

Published Origin source baseline: leorami/project-template@3e7a87624faf4be7503a2829e24d5bdf493762f3, platform-aware visual contract. Its private code stays upstream; use authorized reads to run the existing shared original-byte extractor locally. This public consumer documents only project-specific application, not a new independent visual transport.

## Capture and provenance
- Begin with actual Engineer return, exact remote source, loaded/served source, one canonical app, and Engineer-executed owner journey. Use the existing browser/dev proxy or Playwright against that app. Browser on Ubuntu is supported; no native macOS runner gate. For Dev Proxy public login or an expressly approved public app, reuse scripts/visuals/capture_public_login.py and its existing tests. Never make protected Status/Health/Reports/Calliope or a private Room public to get screenshots.
- Record current testedSourceSha and servedSha (equal full 40-character commits), product/repository, route/state, theme, viewport and physical PNG dimensions, SHA-256, original filename, and source file/lines. Independently establish loaded source; a commit or screenshot claim alone does not establish it. If live bytes differ from tracked source, record precise blocker; do not fake parity. Use desktop 1365x900 and mobile 390x844 by default, plus relevant light/dark and changed state. Capture actual unedited original PNGs, not fabricated mockups. Do not alter the canonical app's data to manufacture evidence.

## Delivery and privacy
- For a genuinely safe synthetic browser capture, use the shared MANIFEST.json and original PNGs in an authenticated Actions ZIP on a separate never-merge evidence branch, with syntheticOnly:true, classification synthetic_no_owner_data, testedSourceSha, servedSha, and frames including file, kind, theme, state, viewport, width, height, sha256. Preserve source snippets and exact run/artifact IDs. Verify every selected image against the independent current source and actual bytes. Use the upstream original-byte extractor by authenticated retrieval, not a public copy of private code. Public artifacts must contain no owner data, private route/host names, tokens, cookie/session details, or private Origin content. An artifact in a public repository is public even when downloaded through an authenticated connector.
- For owner-private original pixels use only an existing owner-approved private authenticated transport (e.g. already authorized Pixel Bridge or supported browser connection). If none delivers actual bytes, preserve locally, record BLOCKED_VISIBLE_PIXEL_TRANSPORT, withhold visual approval, and do not ask the owner to courier files. Public-safe synthetic pixels never prove a private owner session; distinguish both. No new credential/secret or listener created by this policy.
- CTO independently reviews original PNG bytes, hashes and dimensions, exact snippet and actual current UI; materialize verified PNGs as real files under /mnt/data and place 1–3 literal ![caption](sandbox:/mnt/data/filename.png) attachments directly in FINAL ChatGPT reply. Trajectory should render the same verified evidence through its authorized channel; no fabricated success. Client paint remains INLINE_RENDER_UNVERIFIED unless independently observed. Missing private originals, unproven owner runtime and synthetic screenshots remain separate gates.
- For backend-only changes show exact source snippet and test outcome, no unrelated screenshot. Prior V200 Room screenshot was reported by hash only, not delivered or accepted.

## Completion
Primary reports capture source/runtime evidence, privacy classification, original byte transport, source snippet, tests, any actual specialist identities and one terminal receipt. CTO independently verifies and only then authorizes owner UAT when all required gates pass. No live changes, credentials, private artifact publication or protected merge follow from this contract.
