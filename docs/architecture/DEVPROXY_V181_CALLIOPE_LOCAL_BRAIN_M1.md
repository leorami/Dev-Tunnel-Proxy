## The problem is product capability, not merely persona copy

The owner wants Calliope to embody curiosity, warmth, a spunky voice, genuine competence, and the promise of his daughter Colette Calliope without attempting to impersonate a child. The real 503 → "please repair" journey should produce intelligent diagnosis rather than documentation snippets. The next milestones are bounded verified repairs and responsible incident response, not unreviewed arbitrary AI control.

Today the protected secure-mode `POST /devproxy/api/ai/ask` early handler in `utils/proxyConfigAPI.js` calls `explainLocalCalliopeCapability` and `answerFromLocalProjectDocs`; both return `usedAI:false`. The secure `ai/self-check` refuses `heal:true`. The historical legacy `ai/ask` path further down can invoke Docker/edits and remote OpenAI, so **NEVER** reactivate it to restore a charming voice. `status/status.html` currently intercepts repair follow-ups (roughly lines 4565–4593) into canned replies without contacting the model; `status/common.js` keeps local browser chat history but submits only `{query}` to secure Ask. No local model is currently source-wired.

## Remaining Milestone 1 implementation — one coherent owner-visible capability

1. **Local inference, opt-in runtime contract:** inspect actual owner Mac for an available on-device model endpoint (Ollama may be installed elsewhere in the owner's environment but Dev Proxy has no proven configured local inference). Do not assume connectivity from this repo or use the legacy `OPENAI_API_KEY` opportunistically. Prefer an actual local model whose private transport and Docker→host routing are proven with explicit allowlists, fixed endpoint, timeout, response cap and no public listener. Never silently send owner route names, secrets or chat to external vendors. Missing model => honest unavailable state with existing docs answer, `usedAI:false`.
2. **Authenticated session continuity:** one server-trusted, bounded last-six-turn context per **validated owner session**, not client-provided `role:system` history or global shared owner transcript. No prompt logs, GitHub chat leakage, private persisted transcript, raw paths/env/tokens, or long-term memory without explicit owner settings. Existing localStorage can keep UI display history, but cannot grant model or tool authority. Preserve one-send and stop/clear behavior.
3. **Grounded read-only observations:** feed Calliope small current *existing trusted* bounded HTTP HEAD/diagnostic summaries (e.g., observed 503, time/source/classification) and safe documentation references; do not create arbitrary URL fetch, route enumeration or Docker commands. Tool outputs may contain adversarial instructions and must stay data. Return separate observed facts, hypotheses and next recommended read-only check.
4. **Secure Ask wiring BEFORE legacy mutation flow:** reuse the exact `/devproxy/api/ai/ask` owner-auth + trusted-Origin gate and source contract above. Model cannot request shell, edits, reload, worker/notification operations, issue tickets or grant scope. Disallow prompt-supplied systemHint/provider URL/host path. A request like `please repair` prompts an intelligent analysis and *proposed, owner-approved next action*, not a repair.
5. **Real user-facing personality:** `status/status.html` must route repair follow-ups through the safe model/diagnostic path rather than exclusively canned text, with accessible chat, single send, truthful activity and failure, no duplicated assistant bubble, sensible keyboard/viewport behavior. `status/common.js` is another rendering path; preserve both or unify with proven source contracts rather than adding a third chat. Show real visual screenshots **inline** in final owner reply, using an explicitly authorized private browser evidence channel for the protected UI; do not upload private pixels to public Actions artifacts.
6. **Truthful capability status:** `mode:'local_model_readonly'` and `usedAI:true` ONLY after a real local inference response passed the validator; keep `healingPerformed:false`, `liveAttested:false`, `executionAuthorized:false`, `productionChangeAuthorized:false`. Failed/unavailable model must never report an imaginary successful response. Public AI health must not expose model availability or owner's activity.
7. **Independent testing:** RED first for owner session isolation, source/CORS/CSRF, no external model, 503 multi-turn, no mutation, timeout/oversize/bad JSON/prompt injection, fail-closed and fallback, no duplicate UI asks. Run canonical `./smart-build.sh test:unit` and native browser visual tests; real local-model proof on owner host if available, otherwise source-ready **but not** owner experience PASS.
