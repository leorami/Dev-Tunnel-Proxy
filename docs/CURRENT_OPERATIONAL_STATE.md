## Current secure Calliope behavior (not the old self-healing vision)

| Surface | Implemented and source-grounded behavior | What it does **not** prove/do |
| --- | --- | --- |
| **Ask**: authenticated `POST /devproxy/api/ai/ask` | In secure nonroot mode, `utils/proxyConfigAPI.js` consults `explainLocalCalliopeCapability`, then `answerFromLocalProjectDocs` for a bounded local documentation answer. Answers may explicitly show `usedAI:false`. | No general-purpose model inference, no automatic route-context memory, no generic diagnostic invocation or repair by typing `repair`. Historical document excerpts are **not** verified live capabilities. |
| **Audit**: authenticated `POST /devproxy/api/ai/audit` | `utils/rc2-secure-http-audit.cjs` validates an allowlisted route path and probes fixed private `dev-proxy:80` using **HTTP HEAD**, without credentials or arbitrary destination egress. | A 503 is a non-green HEAD observation, **not** proof of the root cause. It does not follow redirects, perform browser GET/JS validation, change nginx, or heal the route. |
| **Self-check**: `POST /devproxy/api/ai/self-check?http=1` with `{"heal":false}` | Source-controlled bounded inventory plus optional read-only HTTP evidence. | No permission to apply a route change, restart a service, mutate configuration, or claim full production health. Requests with explicit healing/targeting are intentionally rejected in secure mode. |
| **Chat interface** | V152 Status and shared Health/Reports use local vendor JS, a single-flight Ask path, a composer/send control and truthful Clear-view language. | **Clear view** hides local messages; it does **not** delete persisted server chat history. No successful auto-repair is established by a message animation. |
| **Reports** | Reviewed `reports.html` expects `{ok,items,pagination}`, renders names via DOM text, and asks for user confirmation before prune operations. | An old page expecting `data.reports` is incompatible with the reviewed source API. |
| **Owner-reviewed fixes** | A narrowly scoped Next.js `/_next/` redirect-repair proposal/review-ticket/CAS flow exists in reviewed source. | It is not a general 503 repair tool. An Ask reply cannot create or inherit authority to execute arbitrary fixes. Legacy direct Docker/shell/remote-AI healing is **not** the approved production path. |

**Important distinction:** The older `docs/CALLIOPE_ASSISTANT.md`, `docs/USER_GUIDE.md` and README describe an aspirational or historical **autonomous self-healing** system, including examples with `{"heal":true}`, generic Docker restarts and automatically applied fixes. Those examples must not be interpreted as current secure-runtime instructions. Follow the actual source, fresh receipts and authorized, transaction-safe capability gates instead.
